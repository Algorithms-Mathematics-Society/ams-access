# P1 review — shared theme and primitives

Reviewed 2026-09-30 against `exectuion-page-wise.md`, AGENTS, the P0 source/state inventory and baseline evidence. The reviewer independently inspected production changes and native rendering, and authored the updated regression tests; the integrating agent separately reviewed those tests.

**Verdict: P1 accepted for the agreed shared-theme scope.** No blocking findings remain. Page-specific redesign and the explicitly listed native/platform checks continue in their later phases.

## Source review

- One generated Astryx Access theme controls canonical palette, typography, radii, motion and component overrides. Legacy aliases point toward canonical roles. The cascade keeps resets below component styling, removes the old universal padding/font overrides, and limits the SSR wrapper correction to the root provider.
- Existing `ams_theme` persistence and route locks remain authoritative. Pre-paint initialization synchronizes Astryx attributes after preference/lock resolution; runtime preference and route changes synchronize those attributes without overwriting saved preference. Returning from locked Home restores the saved light appearance.
- Fonts come from locally installed Geist assets through Next's local font pipeline. Runtime packages are declared directly by their importing workspace packages. API/environment configuration and native enforcement logic are outside this change.
- Home Button preserves native events, ref, type, disabled semantics and children. The compatibility Field deliberately remains native to preserve IDs, uncontrolled defaults and event contracts; new forms can opt into the discovered Astryx field API. Existing critical overlay owners remain intact; the new shared native Dialog is opt-in.
- Generated fallback CSS uses explicit HTML mode/lock selectors and derives palette/component declarations from the official generated theme. Its documented scope is one root Access theme. It still requires CSS layers and color mixing; it is not a certification of every older platform allowed by the native packaging minimums.

## Findings and corrections

1. A draft legacy `--transition-slow: var(--transition-slow)` self-cycle was removed. The alias-graph regression test now rejects this class of defect.
2. The theme workstream removed inherited blue information/progress overrides, fixed invalid `light-dark()` usage around entire shadow values, and calibrated Submit pressed-state contrast. Native computed shadows and generated normal/hover/pressed color pairs are covered.
3. The reviewer initially reported a false secondary-text contrast failure because the new test helper accidentally used sRGB gamma 2 rather than 2.4. This was corrected before acceptance, with both a known `#777777`/white ratio (4.478089...) and black/white ratio (21) calibration fixture. The retained darker secondary text is valid, but the initial 4.39:1 report was **not** a real UI defect.
4. The integrating agent found that unchanged legacy solid-purple buttons still specified white foregrounds while the new dark accent is lighter. This was corrected through `--color-on-accent` in CSS actions and inline Home/preflight/recovery/Submit controls. Normal and enabled hover/brightness/opacity states now pass calibrated contrast tests. Native Login and Onboarding buttons were additionally verified against the canonical Submit color pair in light/dark modes. The Home Resume hover handler now preserves the shared monochrome primary role.

## Scope and evidence limits

The complete browser baseline still records 28 permission-denied exceptions and two onboarding dry-run hydration mismatches (production React error 418), matching P0's categories. Capture completion does not mean all pre-existing runtime issues are fixed. The unchanged Home practice fixture still shows `NaNh left`; stale error/empty copy and fixed-light legal surfaces remain assigned to their page phases.

The local WebKit probe uses software rendering and static real-component markup, not the full Tauri workflow. It does not certify older WebKit binaries, macOS/Windows WebViews, camera/microphone, fullscreen/keyboard lockdown, judging, autosave, or authenticated exam operations. Fixture traffic is isolated from actual participant sessions. Existing page-specific styling remains for P2–P8.
