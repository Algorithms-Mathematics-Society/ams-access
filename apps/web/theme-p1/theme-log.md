# P1 canonical theme and CSS change log

Date: 2026-09-30. Owner: theme subagent; independent review performed by the P1 reviewer. This log describes the shared foundation slice. Individual Welcome/Login, Home, onboarding, contest and Results layout redesigns remain in their planned later phases.

## Files and ownership

- `src/theme/accessTheme.ts`: sole authored Astryx palette, typography, motion/radius and component theme definition, extending installed `neutralTheme` 0.1.8.
- `src/theme/access.js`, `access.d.ts`, `access.variants.d.ts`, `accessTheme.css`: generated by the official Astryx CLI. Runtime imports the built `access` module, avoiding runtime CSS injection and the source module's dependency weight. Custom Button variant is `submit`.
- `src/theme/build-theme.mjs`: reruns the official CLI and derives the two adapters below; it does not maintain a second palette.
- `src/theme/compatibility.css`: generated RGB triplets for existing `rgb(var(--accent-rgb) / alpha)` consumers. Values are extracted from canonical accent/text-accent tokens. Light selector excludes dark-locked routes.
- `src/theme/fallback.css`: generated explicit light/dark tokens and selectors for the app's single root Access theme. It flattens the CLI's `@scope` output and resolves `light-dark()` expressions, including inherited core defaults, so those two recent CSS features are not required to render the palette and component overrides. The official scoped CSS loads after this adapter for browsers that support it.
- `src/app/globals.css`: one-way compatibility aliases, explicit cascade and existing legacy page rules. Existing page geometry is retained; no route logic, auth/API calls, native permissions or editor behavior changed here.

## Decisions

1. Canvas/panels are neutral: dark `#0a0a0a` / `#121212` / `#1a1a1a`; light `#fafafa` / white / `#f5f5f5`. Required secondary text uses opaque readable neutrals instead of numerous low-opacity tiers. Light secondary text is `#5b5b5b`. The reviewer initially reported the earlier `#5e5e5e` as failing AA, but that report was a false positive caused by a test-helper gamma exponent of 2 instead of 2.4. The corrected test includes a known reference pair; both shades pass, and the slightly stronger current shade is retained.
2. Purple belongs to focus, compact active markers/branding and explicit Submit. General Astryx primary buttons use inverted neutral/body; Submit uses accent/on-accent with separate contrast-safe pairs for each mode. Legacy route accent usage remains until each page migration.
3. Status text, dots, badge backgrounds and borders use semantic green/amber/red roles. General progress/info UI is neutral. Removed inherited literal blue from accent StatusDot, progress, info badge/banner, and attention inset shadows.
4. Geist Sans/Mono tokens refer to distinct loader variables `--font-geist-sans`/`--font-geist-mono`. The root agent bundles fonts and installs their variables on HTML so inherited legacy aliases resolve at the root. No theme requests a remote font URL.
5. Layers are `reset, theme, base, astryx-base, astryx-theme, components, utilities`. Imported Astryx reset/core precede adapters/theme. Removed the unlayered universal reset and broad input `!important` font/appearance/shadow rules. Existing page rules now occupy `components`; new theme components retain their own padding and status treatment. Existing legacy typography classes remain scoped to their named classes until their route slices.
6. Legacy aliases resolve canonical roles, including surfaces, home tints, text, borders, radius, shadows and status. Duplicate canonical names were removed. `--transition-slow` is deliberately inherited rather than self-aliased. No canonical color literals are authored in a `:root` override.
7. The immediate root Theme wrapper inherits HTML color-scheme. The separate provider work owns saved preference, prepaint mode and route locks. Fallback selectors use HTML preference plus the lock, never the provider's SSR default mode.
8. Adapter scope is deliberately the app's single root theme. Nested differently named themes are not supported by the fallback; adding them requires extending the adapter. This does not certify all historic operating-system WebViews. CSS layers and the existing modern CSS baseline are still required; actual older macOS/Windows engines remain a release verification task. Native current WebKit checks are recorded in the independent review.
