### Post-pull invariants / known risks

1. **Handle login:** `SlipForm.tsx` consumes `formatHandle`: lowercases, removes suffix from first `@`, allows `[a-z.-]`, caps64. Password formatter uppercases alphanumerics, three groups of four. Fixed `@access` suffix must not enter the editable field or disappear on paste; preserve autocomplete, the intentionally visible formatted password, and error handling. Existing cross-layer inconsistency: `src/lib/proctor-api.ts` `studentLogin` still uppercases `login_id` and contains printed-slip comments. Investigate separately with auth contract evidence; P0 does not change credentials or network behavior.
2. **Active-problem Attempts:** `client.tsx` stores the full session list once; `useMemo(attemptsForProblem(allSubmissionsList, activeQLabel))` derives visible rows. Keep derived filtering, newest-first list and active-problem empty copy in `TerminalPanel.tsx`; late A polling must never repaint B with A attempts. Runs are fetched separately and are absent from scored submission list by server contract. Preserve newest verdict and pending-submit derivation from the same filtered list.
3. **Scroll/collapse risks:** onboarding progress plus100vh frame, Results/legal scrollports, Settings560 minimum, contest optional banner and error rows, expanded/collapsed camera reserve and fixed footer202 all need actual measurements after typography changes.
4. **Theme risks:** introducing Astryx reset alongside Tailwind can change box sizing, control defaults and global type rules. Global font change alone leaves hardcoded Inter/JetBrains surfaces untouched. Semantic verdict colors must be distinguished from decorative purple when mapping.
5. **Content inconsistencies:** absent invite-code field referenced by Home empty text; Settings placeholder and stale version; completion/results copy disagreement. Only change copy after verifying current behavior in its planned slice.
6. **Evidence limits:** browser fixtures may illustrate all native states but cannot verify fullscreen, keyboard lock, app closing, display/VM detection, helper setup, camera transfer or teardown. No live participant credentials or organizer writes are needed for P0. Tauri testing remains required in later phases; no native state is marked verified here.
